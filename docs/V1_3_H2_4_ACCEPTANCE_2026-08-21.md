## 1. Reopening decision

V1.3-H.2.4 is reopened.

The prior candidate remained fail-closed, but a newly reproduced concurrency interleaving showed that it could lose the durable explanation H.2.4 is intended to guarantee.

The missing interleaving is:

```text
canonical revision v1 is accepted before producer egress
producer executes against v1
v2 commits during producer runtime
post-producer revalidation correctly detects v1 -> v2
before the first H.2.4 attribution write, v3 commits
v2 is therefore superseded by v3
prior persistence logic requires observed v2 to still be ACTIVE
first attribution write fails closed
no stale canonical effect is committed, but the v1 -> v2 explanation is lost
```

This does not create unsafe canonical truth. It is nevertheless an H.2.4 acceptance blocker because H.2.4 exists to make this exact post-producer stale-work event durable and explainable.

Permanent boundaries remain unchanged:

> The Immune System may restrict or stop execution. It never grants authority, autonomy or permission.

> Optimistic-concurrency contention is not automatically a safety fault.

## 2. Verified cause

The prior first-persistence contract reconciled the observed revision with durable identity but also required:

```text
observed_revision.lifecycle_status == "active"
```

That requirement is valid at event-detection time but too strong at persistence time.

`observed_current_lifecycle_status = active` is an event-time statement: v2 was the current ACTIVE revision when the post-producer check observed the v1 -> v2 advance. A legitimate later v3 may supersede v2 before the attribution pair is written.

Historical replay already permitted later supersession after attribution existed. The missing case was later supersession before the first attribution write.
