## 3. Canonical lineage reconciliation

The final repair deliberately does not duplicate canonical revision-chain logic.

It refreshes the session's revision rows from the database and delegates complete aggregate proof to:

```text

```

That existing shared validator proves:

- contiguous versions beginning at 1;
- exactly one latest ACTIVE revision;
- all earlier revisions SUPERSEDED;
- exact supersession predecessor identity;
- aggregate identity;
- each revision's canonical G.1/G.2/G.3/semantic lineage and fingerprints.

H.2.4 then requires the resolved and observed event-time revision IDs to be present in that validated aggregate chain with exactly the captured versions, and the observed index must be strictly after the resolved index.

This preserves the permanent V12 doctrine that canonical eligibility lineage has one shared domain validator rather than parallel safety-specific copies.
