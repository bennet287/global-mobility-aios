## 1. Permanent adoption principles

Third-party infrastructure may parse, execute, retrieve, observe, scan, render, evaluate, optimize, coordinate, remember or connect, but may not become authoritative for:

- Global Mobility domain meaning;
- legal status;
- Evidence state;
- certification/publication state;
- human-review requirements;
- organizational authority;
- Mission/WorkItem semantics;
- semantic OrganizationActivity;
- canonical business outcomes.

Preferred pattern:

```text
AIOS domain / Organization OS
        ↓
AIOS-owned capability contract
        ↓
AIOS Context / Canonicalization / Command / Execution layers
        ↓
external runtime / technology
```

Hard canonicalization invariants remain:

```text
conversation != authority
message != decision
memory != Evidence
memory != VerifiedRule
provider event log != canonical AIOS Activity automatically
```

## 6. Adoption gate for every Munder subsystem

A donor component does not become production architecture until it demonstrates, as applicable:

- AIOS semantic sovereignty;
- Human Owner / Board authority preservation;
- tenant isolation;
- sensitivity/privacy boundaries;
- typed capability contracts;
- no canonical mutation bypass;
- capability/authority/autonomy/risk separation;
- traceability;
- deterministic failure behavior;
- idempotency/concurrency safety;
- bounded resource use;
- rollback/replacement strategy;
- focused acceptance tests;
- full regression where required;
- repository-policy compliance.

Every donor subsystem is classified:

