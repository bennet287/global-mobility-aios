## 1. Acceptance decision

V1.3-H.2.3 is accepted and sealed.

The increment establishes trusted, durable attribution for one genuine G.5 optimistic-concurrency failure: a reassessment arrives with an expected canonical eligibility revision that is lower than the current single ACTIVE revision, and that conflict is discovered before producer provider egress.

The increment is observation/provenance only. It does not treat normal optimistic-concurrency contention as an automatic safety fault and does not grant authority, autonomy or permission.

Permanent boundary:

> The Immune System may restrict or stop execution. It never grants authority, autonomy or permission.

H.2.3 additionally preserves:

> Optimistic-concurrency contention is not automatically a safety fault.

## 2. Accepted classification boundary

H.2.3 attributes a revision conflict only when:

```text
canonical eligibility aggregate exists
exactly one ACTIVE revision exists
expected_eligibility_revision_version >= 1
expected revision < current ACTIVE revision version
conflict is detected before producer provider egress
```

The accepted canonical signal is the narrow `EligibilityRevisionPreconditionConflict` subtype.

The following remain ordinary fail-closed G.5 errors and do not create H.2.3 incidents:

```text
missing expected revision
expected revision < 1
expected revision > current revision
expected revision with no current canonical revision
multiple ACTIVE revisions / aggregate corruption
tenant / aggregate integrity failures
post-provider revision races
request/schema errors
```

This asymmetric classification is deliberate false-positive containment. A lower-than-current expectation demonstrates superseded observed state; a future expectation does not.


The observed revision identity is reconciled against the durable canonical revision before writing the pair.

## 4. Accepted safety semantics

H.2.3 does not add `revision_conflict` to the H.2.1 recurrence threshold.

Accepted semantics:

```text
severity                  warning
automatic circuit action  none
recurrence threshold      none
circuit                    remains CLOSED
blast radius              none
authority effect           none
autonomy effect            none
automatic retry            none
automatic rebasing         none
```

Repeated revision-conflict warnings therefore remain observation-only in H.2.3.

## 5. Integrity and replay acceptance

Acceptance proves:

- the attribution + immune warning are one transactional pair;
- an injected failure after attribution staging rolls the pair back;
- exact replay reuses the existing pair;
- a torn pair fails closed rather than being silently repaired;
- replay with a changed conflict snapshot fails closed;
- stale pre-egress conflict produces zero producer and verifier provider calls;
- post-provider revalidation remains generic stale state rather than being misattributed as the pre-egress conflict subtype;
- nonexistent-current, missing and future expectations do not create false-positive H.2.3 incidents;
- repeated revision conflicts do not open the aggregate circuit.
