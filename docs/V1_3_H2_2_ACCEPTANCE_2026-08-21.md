## 1. Acceptance decision

V1.3-H.2.2 is accepted and sealed.

The increment establishes trusted, durable attribution for G.4 eligibility producer/verifier runtime-health failures without introducing a provider-health score, wider quarantine rule, automatic recovery, authority grant or autonomy grant.

The accepted architectural boundary is:

> Runtime-health measurement and provenance are established before any wider runtime-health restriction policy is authorized.

The permanent constitutional boundary remains:

> The Immune System may restrict or stop execution. It does not grant authority, autonomy or permission.

## 2. Accepted behavior

For a G.4 producer or verifier runtime-health failure, AIOS persists one deterministic atomic pair in the canonical aggregate immune stream:

```text
organization.immune.eligibility_runtime_health_attributed.v1
+
organization.immune.eligibility_incident.v1
  kind = runtime_health_failure
```

The attribution is derived only from the trusted server-side `GovernedEligibilityExecutionPlan` / `AgentRuntimeProfile` and records:

```text
execution_role
failure_stage
position_key
runtime_profile_key
runtime_profile_version
runtime_profile_fingerprint
runtime_class
adapter_key
provider_key
model_key
independence_group
```

The HTTP request cannot select or replace these values.

Runtime-health incidents remain warning-only:

```text
severity                 = warning
automatic circuit action = none
control_effect            = observation_only
authority_effect          = none
```

Repeated runtime-health warnings do not participate in the H.2.1 verifier-disagreement recurrence threshold and do not open a circuit in H.2.2.

## 3. Integrity and replay acceptance

Acceptance includes the following failure semantics:

- the attribution Activity and immune warning are one transactional pair;
- a failed paired write rolls back the staged attribution;
- exact replay reuses the durable pair rather than creating timestamp drift;
- a legacy/torn pair fails closed rather than being silently backfilled;
- the same incident key cannot be replayed with changed trusted runtime identity;
- verifier runtime attribution preserves proposal causation and trace correlation;
- H.2.1 behavior remains unchanged.

No pre-H.2.2 historical warning is rewritten retroactively.
