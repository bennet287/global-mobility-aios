# Monitoring

OpenTelemetry is the current vendor-neutral engineering telemetry boundary. The
API can instrument FastAPI and export OTLP when explicitly enabled, while E1
correlates the bounded Austria L cycle and its specialist executions.

```text
OTEL_ENABLED=true
OTEL_EXPORTER_OTLP_ENDPOINT=<operator-managed OTLP endpoint>
OTEL_SERVICE_NAME=global-mobility-aios-api
OTEL_SERVICE_VERSION=<deployed source version>
```

Organization spans accept only durable execution identifiers, position key,
latency/retry counts, freshness count and bounded outcomes. Never attach tenant
keys, prompts, provider responses, documents, Evidence content, credentials, or
personal case data.

```text
engineering telemetry != canonical OrganizationActivity
telemetry availability != authority
```

An OTel-compatible collector/backend is replaceable. Langfuse remains a possible
LLM/agent observability backend behind this boundary; Prometheus, Grafana and Loki
remain deployment candidates rather than accepted dependencies.
