# AIOS V2 Color System

## Objective

Color communicates hierarchy, semantic state, truth class, and restrained departmental identity.

It must never become decoration-first branding.

## Foundation layers

Required semantic tokens:

- canvas
- base surface
- raised surface
- inset surface
- overlay
- spatial HUD surface
- subtle border
- strong border
- primary text
- secondary text
- tertiary text
- inverted text

## Semantic state families

Define distinct treatment for:

- success
- information
- warning
- critical
- blocked
- awaiting Owner
- active
- queued
- completed
- unavailable
- stale
- unknown

Color is never the sole carrier of meaning.

Pair with:
- icon
- label
- shape
- pattern
- text

as appropriate.

## Truth classes

Visually distinguish:

- canonical
- human-authoritative
- AI recommendation
- historical reconstruction
- memory/aggregate
- prediction
- simulation
- unsupported/unavailable

The distinction should be subtle enough for enterprise use, but unmistakable when compared.

## Department accents

Directional only until prototype review:

- Executive — warm champagne / muted metallic
- Technology — precise cool blue
- Security — indigo / graphite
- Regulatory — warm amber / parchment
- Operations — teal
- Intelligence — cool cyan

Department identity is secondary to semantic truth.

## Theme behavior

Support:
- light
- dark
- system

The same semantic meaning must survive both themes.

Dark mode must not transform routine information into neon.

## Forbidden

- generic AI-purple identity
- rainbow department coding
- unrelated one-off page colors
- high-saturation status overload
- color-only authority indication
