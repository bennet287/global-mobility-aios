# AIOS V2 Typography

## Direction

Typography should feel editorial, precise, premium, and highly legible.

Geist / Geist Mono remain suitable baseline candidates.

## Type roles

Define:

- display
- page/executive title
- section title
- object title
- body
- compact body
- label
- caption
- metadata
- status
- numeric
- technical/provenance

## Hierarchy

The type system must make cognitive depth visible.

Primary meaning:
larger, calmer, cleaner.

Evidence:
smaller but still readable.

Technical/provenance:
compact, optionally mono, clearly secondary.

## Mono usage

Use monospace deliberately for:

- IDs
- hashes
- source fingerprints
- provider/model identifiers
- contract versions
- exact timestamps where audit context needs it
- diagnostics

Do not use mono as “futuristic decoration.”

## Numeric typography

Mission counts, risk totals, evidence counts, and cost metrics should use stable numeric alignment where useful.

## Line length

Long-form evidence/regulatory reading should prioritize comfortable measure and paragraph spacing over dashboard density.

## Capitalization

Avoid excessive all-caps.

Use uppercase sparingly for:
- short metadata labels
- compact state markers
- technical tags

## Accessibility

Typography must remain legible at:
- 200% zoom
- high-density operational views
- dark/light theme
- reduced viewport widths
