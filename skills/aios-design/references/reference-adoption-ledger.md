## HorizonX free-use boundary

AIOS may use HorizonX without a paid subscription only as a **public visual/motion/spatial reference and experimentation benchmark**.

Allowed AIOS use:

1. inspect publicly visible previews, interactions, motion behavior, composition, spatial depth, and atmosphere;
2. use publicly accessible interactive tools where available;
3. extract abstract principles such as perspective treatment, scene pacing, lighting logic, transition structure, spatial hierarchy, or interaction rhythm;
4. recreate those principles as **original AIOS-native code and assets** using the existing React/Next.js/Three.js stack or other already-approved project technology;
5. use HorizonX screenshots/previews as quality-comparison references during visual review without treating them as AIOS design authority.

Not allowed under the free-reference posture:

1. bypassing download/paywall restrictions;
2. scraping, reconstructing, or extracting gated source code, Figma assets, or premium files;
3. copying a premium component/template closely enough that AIOS becomes a derivative skin;
4. assuming a HorizonX commercial asset license applies when the asset was not legitimately obtained;
5. importing external visual semantics that conflict with AIOS truth, authority, accessibility, reduced-motion, responsive, or provenance requirements.

The intended transformation path is:

`public HorizonX preview/tool → identify transferable technique → define AIOS-specific rule → implement originally → desktop/phone browser proof → visual/UX + anti-AI-slop review → keep only if recognizably AIOS`

For Living HQ specifically, HorizonX may help benchmark WebGL/Three.js depth, architectural atmosphere, restrained cinematic lighting, spatial transitions, and high-end interaction polish. The target remains an original AIOS Living Organization where departments, persistent employees, supported work, skills, tools, evidence, handoffs, and authority are the actual information architecture rather than decorative 3D wallpaper.

## Adoption protocol

For every new external reference or skill:

1. record exact source/repository and current license posture;
2. define the AIOS question it is intended to answer;
3. extract the transferable principle;
4. record what must not be copied or treated as authoritative;
5. define the AIOS-specific adaptation;
6. evaluate accessibility, performance, dependency and security consequences;
7. cite implementation/review evidence when adopted;
8. update the Master Plan only when adoption materially changes the execution baseline.

## Permanent boundary

`canonical truth → AIOS Design Constitution → Master Plan → phase specification → external reference → implementation convenience`

No external source may fabricate organizational state, weaken authority boundaries, replace structured accessibility, or turn presentation into canonical truth.
