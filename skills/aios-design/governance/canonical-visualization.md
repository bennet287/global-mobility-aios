# Canonical Visualization

## Principle

Canonical state is represented clearly, but presentation remains presentation.

## Required distinctions

- canonical current
- projection/read model
- renderer
- human authority
- historical reconstruction

## Scene

The scene may visualize canonical projections.

The renderer remains non-authoritative.

## Structured UI

Structured details should expose canonical basis/provenance at the appropriate information depth.

## Mismatch

If roots/versions/state projections mismatch:
- do not mix states
- show visible partial/reconciliation state
- allow refresh/retry
- do not synthesize locally

## Labels

Do not overuse “canonical” in primary user copy.

Use plain operational language first; expose canonical basis in disclosure/inspection.
