# Task flows and continuity

Read this alongside `navigation.md` and `interaction-design.md`.

| Starting need | Read path | Explicit action boundary |
|---|---|---|
| Owner attention | Home → Decision → supporting Evidence → decision lineage | Reviewed outcome and rationale submitted to existing Board API |
| Understand delivery | Mission → participant → work item → recorded handoff | Selection changes presentation only |
| Verify a claim | Rule → exact official source ID → exact snapshot ID → provenance | Active status does not establish freshness or correctness |
| Explain change | History → event cursor → reconstructed state → comparison | Current-record links must identify the switch from history |
| Professional execution | Work → profile/case → relevant tool or review queue | Existing authentication and workflow policies remain authoritative |
| Mobility user | Secure access → case → requested document/timeline/message | No staff API or organization roster substitutes for protected case access |

Keep selection in the URL when the identifier is suitable for normal application
navigation. Do not put credentials, portal grants or case contents into navigation
history. Closing an inspector returns focus to its originating control when it
still exists. A record omitted by a bounded read remains explicitly unreturned.

Prefer existing public domain APIs. A presentation adapter may join exact IDs;
it must not join by a similar title, infer an assignment or create an event.
